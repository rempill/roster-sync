RosterSync local demo

All six folders live in the main working directory.
They are ordinary folders, not Git branches or worktrees.
No commits or pushes are needed.

branch1: FastAPI matching engine, weighted compatibility and matching tests.
branch2: ICS ingestion, timezone and recurrence support, weekly bitmask operations.
branch3: NestJS API, Prisma schema, PostgreSQL persistence, JWT and vacancy locks.
branch4: Authenticated Socket.io connections and private notification rooms.
branch5: Next.js 15 dashboard, profiles, calendars, heatmap and team workflows.
branch6: Docker Compose, test automation, browser checks and CI workflow template.

Start from the repository root:
docker compose -f branch6/compose.yml up --build -d --wait --wait-timeout 180

2. Edit Profile to change skills and ambition.
3. Open Schedule, set week to 2026-11-09 and import branch2/demo-calendar.ics.
4. Compare availability with StudyFlow and inspect the shared-time heatmap.
5. Discover teams and apply to StudyFlow.

8. Inspect My team, invite Andrei and export the roster CSV.
9. Sign in as Andrei and accept the invitation in Requests.

The demo validates the university email domain but does not verify email ownership.
It does not connect to university SSO.
Weekly availability uses 336 half-hour slots starting Monday 00:00.
The UI displays weekday slots from 09:00 to 18:00.
ICS imports replace availability for the selected week using the weekday baseline.
The demo stores a representative weekly availability grid, not multiple calendar weeks.
Recurring events are expanded for the selected Monday and Europe/Bucharest timezone.
Matching weights: schedule 45%, required skill coverage 35%, ambition 20%.
Four shared hours reaches the schedule target.
A student can belong to one team.
Team owners occupy one seat.
Approvals and invitation acceptance lock the team row in a PostgreSQL transaction.
Full teams remain visible but cannot receive new applications or invitations.

Unit tests:
docker compose -f branch6/compose.yml exec -T matching python -m unittest -v test_matching test_scheduling

Integration tests:
docker compose -f branch6/compose.yml exec -T core node checks/integration.mjs

Persistence test, after integration:
docker compose -f branch6/compose.yml restart core
docker compose -f branch6/compose.yml up -d --wait --wait-timeout 180
docker compose -f branch6/compose.yml exec -T core node checks/integration.mjs --persistence

Browser tests:

node branch6/node_modules/playwright/cli.js install chromium --only-shell
node branch6/checks/browser.mjs
